# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

Every Half asset & tools (CCDC) management web app. React 19 · Vite 8 · TypeScript 6 · TanStack Router/Query/Table · Tailwind 4 · shadcn/ui · Zustand · Zod 4 · i18next. Backend is the sibling repo `../eh_am_backend` (API under `/v1`, port 3006).

README, code comments and `.env*.example` files are written in **Vietnamese**; match that when adding comments. The codebase uses heavy `⚠️`-prefixed "why" comments at non-obvious decisions — read them before changing the surrounding code.

Status: the app shell, API client, auth flows, i18n, CSP and error pages are done. Business screens and project-specific shared components are not built yet (the dashboard is a placeholder); they wait on design / the Master Blueprint.

## Commands

```bash
npm run dev                  # http://localhost:5175 (strictPort — see below)
npm run build                # tsc -b && vite build
npm run preview              # serve dist/ on 5175 — the only way to verify CSP
npm run typecheck
npm run lint                 # eslint (no-console is an error)
npm run format               # prettier + import sorting + tailwind class sorting
npm test                     # vitest in headless Chromium (browser mode)
npm run knip                 # unused files/exports/deps
npm run test:browser:install # one-time Chromium download for Vitest

# single test file / single test
npx vitest run --browser.headless src/lib/safe-redirect.test.ts
npx vitest run --browser.headless -t "test name"
```

Before committing: `npm run precommit && npm test`.

- Port **5175** is fixed with `strictPort`; backend CORS only allows `http://localhost:5175`. Don't change it to "fix" a port clash.
- Tests run in a real browser (Playwright/Chromium), not jsdom. `src/test-utils/setup.ts` initializes Zod config + i18n before every test.
- Test env vars live in `vite.config.ts` → `test.env`, **not** `.env.test` (gitignored). The test API URL is a deliberately non-existent `.invalid` host — tests must not hit the network.
- If a test file fails with "Vitest failed to find the runner" right after adding a dependency, just rerun (Vite re-optimized deps mid-run).

## Architecture

**Boot order matters** (`src/main.tsx`): `./lib/zod-config` must be the first import (non-JIT Zod for CSP + localized validation messages), then i18n, then QueryClient and Router. The file has `// sort-imports-ignore` so Prettier doesn't reorder it.

**Env** (`src/config/env.ts`): all `VITE_` vars are validated at startup and throw on invalid values. They are public (bundled), so never add secrets. `VITE_API_BASE_URL` includes `/v1` with no trailing slash. Devtools are hard-disabled in production builds regardless of env.

**Routing**: TanStack Router file-based routing in `src/routes/`; `src/routeTree.gen.ts` is generated by the Vite plugin, so don't edit it. Route files stay thin and render components from `src/features/<feature>/`. Groups: `(auth)` sign-in/forgot/reset password, `(errors)` 401/403/404/500/503, and `_authenticated` for everything behind login.

**Auth guard** (`src/routes/_authenticated/route.tsx`) is the *only* place that redirects on auth failure (the QueryClient deliberately does not redirect on 401). `beforeLoad` redirects to `/sign-in?redirect=…` when there are no tokens. `loader` calls `ensureQueryData(meQueryOptions())`, and a user with no roles goes to `/403`. `redirect()` is thrown, so catch blocks must rethrow when `isRedirect(error)` is true.

**Session** (`src/stores/auth-store.ts`, Zustand): the backend returns encrypted tokens that the frontend can't decode, so roles come only from `GET /auth/me` (`meQueryOptions`, `staleTime: Infinity`; invalidate `AUTH_ME_QUERY_KEY` after locale or role changes). Tokens are stored in `sessionStorage` under `eh.am.session`. `hasAnyRole` / `canAccessApp` only control what the UI shows; the backend enforces the real permissions. Roles are platform-wide or per-location (`locationRoles`), and super admin bypasses role checks.

**API layer** (`src/lib/api/`):

- `client.ts`: an axios instance with proactive refresh (60s before expiry) and reactive refresh on 401, merged into a single in-flight refresh call. It normalizes every error to `ApiError`, so never check `instanceof AxiosError`. Never call refresh manually.
- `*.api.ts`: thin wrappers, one function per endpoint, with no store writes. `*.queries.ts` holds the `queryOptions` factories.
- `error-code.ts` is a hand-maintained mirror of the backend's `error-code.const.ts`. **Branch on `error.code`, never `error.message`**, because messages are localized.
- `handle-api-error.ts`: produces a translated toast with the `requestId`. It is wired as the global mutation `onError`, and a per-mutation `onError` *replaces* it rather than adding to it. `shouldRetryQuery` is the query retry policy.

**i18n** (`src/lib/i18n/`): `vi.ts` is the source of truth; `en.ts` is typed `TranslationKeys`, so a missing English key is a compile error. Add every UI string to both files. After login, the user's `preferredLocale` overrides `VITE_DEFAULT_LOCALE`.

**Zod** (`src/lib/zod-config.ts`): generic bilingual validation messages ("required", "max N chars") are already provided. Only pass `{ message }` when you need custom wording.

**Security**: `vite.config.ts` injects a strict CSP `<meta>` **at build time only** (`script-src 'self'`, no unsafe-inline/eval; `connect-src` includes the API origin, so changing the API domain requires a rebuild). Don't add inline scripts or `eval`-based libs. `?redirect=` must go through `src/lib/safe-redirect.ts`. The reset-password page reads the recovery token from the URL once and then strips it.

**UI**: `src/components/ui/` is shadcn/ui (`npx shadcn add …`). Don't hand-edit it; it is excluded from eslint, knip and coverage. Shared table: `src/components/data-table/` with URL-synced state via `src/hooks/use-table-url-state.ts`. Layout/sidebar live in `src/components/layout/`.

## Conventions

- Prettier: no semicolons, single quotes (JSX too), `trailingComma: es5`, 80 cols. Import order is enforced by `@trivago/prettier-plugin-sort-imports` (see `.prettierrc`), and Tailwind classes are sorted inside `cn()`/`clsx()`.
- ESLint enforces `consistent-type-imports` with inline style (`import { x, type Y }`), `no-duplicate-imports`, and prefixing unused vars with `_`.
- Path alias `@/` → `src/`.
- Tests sit next to their source as `*.test.ts(x)` and use `vitest-browser-react`.

## Chuẩn UI bắt buộc (rút ra từ manual test — áp cho MỌI trang, tránh lặp lỗi)

Sáu chuẩn dưới đây là bắt buộc cho mọi màn hình mới; đừng dựng trang mà thiếu một trong số đó.

1. **Khung trang:** mỗi trang bọc trong `<Header>…</Header>` (Search + ThemeSwitch + ConfigDrawer + ProfileDropdown) rồi `<Main>…</Main>` (`@/components/layout`). `Main` cho gutter chuẩn (`px-4 py-6`) + max-width — KHÔNG render nội dung trần trong `SidebarInset` (sẽ dính sát sidebar, thiếu thanh top).
2. **Ngôn ngữ nhất quán + trường bắt buộc:** bản `vi` phải dịch **đủ tiếng Việt**, không trộn Anh-Việt trong một nhãn. Thuật ngữ nghiệp vụ dịch: *location → địa điểm*, *cost center → trung tâm chi phí* (chỉ giữ tiếng Anh cho token kỹ thuật thật sự phổ quát: API, QR, URL, FAST…). `en` giữ đúng cùng bộ khoá. Trường bắt buộc: gắn `<RequiredMark/>` (`@/components/required-mark`, dấu `*` đỏ) sau nhãn.
3. **Dialog rộng rãi:** dialog form dùng `className='sm:max-w-2xl'` trở lên, `grid gap-4`; đừng để hẹp/chật. Màn rộng thì tận dụng, không tiếc diện tích.
4. **Trạng thái rỗng/thiếu phụ thuộc kèm hành động:** khi chặn do thiếu dữ liệu phụ thuộc (VD: chưa có trung tâm chi phí đang hoạt động), ngoài câu thông báo phải có **nút đưa tới luồng khắc phục** (VD: "Tạo trung tâm chi phí" → điều hướng sang màn tạo). `EmptyState` luôn có `action`.
5. **Địa chỉ VN:** dùng `AddressPicker` (`@/components/address-picker`): Tỉnh/Thành → Phường/Xã (dropdown khi có dữ liệu, tạm text) → số nhà/tên đường; gộp thành một chuỗi khớp trường `address`. Dữ liệu 34 tỉnh ở `@/lib/data/vn-provinces.ts` (TẠM — cần nạp dataset phường/xã chính thức, không bịa).
6. **Gợi ý mã danh mục:** ô mã của danh mục có mã dạng "tiền tố + số" hiện chip gợi ý mã kế tiếp (`suggestNextCodes`, `src/features/master-data/next-code.ts`) — bấm để điền, người dùng vẫn tự gõ được.

7. **Văn phong i18n qua humanizer:** mọi câu chữ hiển thị (bản `vi` và `en` trong `src/lib/i18n/locales/`) — nhất là mô tả, thông báo, câu lỗi, trạng thái rỗng — PHẢI soát bằng skill `humanizer:humanizer` trước khi chốt. Viết ở **góc độ người dùng platform**: rõ, mạch lạc, dễ hiểu, đúng việc họ đang làm; không lên giọng máy/AI, không sáo rỗng. Nhãn ngắn (nút, cột) giữ gọn tự nhiên; câu dài phải đọc như người viết nội dung viết, không phải bản dịch máy.

8. **Con trỏ theo trạng thái + khả năng tiếp cận (a11y) — hay quên, BẮT BUỘC:**
   - **Con trỏ (cursor) khai theo từng trạng thái:** phần tử bấm được → `cursor-pointer`; disabled → `cursor-not-allowed` (KHÔNG dùng `pointer-events-none` che mất con trỏ); đang tải/pending → gắn `aria-busy` để ra `cursor-wait`; gợi ý/giải thích → `cursor-help`. `Button` chung đã có sẵn các trạng thái này; nút đang chờ mutation phải truyền `aria-busy={isPending}`.
   - **A11y tối thiểu mọi component tương tác:** input có `<label>` liên kết (hoặc `aria-label`); lỗi field qua `aria-describedby` + `aria-invalid`; icon-only button có `aria-label`/`sr-only`; dialog bẫy focus + đóng bằng `Esc` + trả focus; trạng thái không chỉ dựa vào màu (thêm chấm/chữ như `StatusBadge`); ảnh trang trí `aria-hidden`; vùng chạm ≥ 44px trên mobile; tôn trọng `prefers-reduced-motion`.
9. **Nút phụ dạng chữ (secondary/link action):** dùng `LinkButton` (`@/components/link-button`) — gạch chân mờ sẵn từ đầu, hover đổi chữ + gạch chân sang `primary`, KHÔNG đổi độ đậm (tránh nhảy layout). Nút chính (Lưu/Thêm) dùng `Button` `size='lg'` cho thoáng, không để nhỏ chật.

10. **Enum/hằng DB → i18n, KHÔNG show mã thô (hay quên):** mọi giá trị enum/hằng từ database (trạng thái `ACTIVE`/`INACTIVE`, loại `STORE`, nhóm lý do `DISPOSAL`, `reason_group`…) PHẢI map sang chữ i18n (`t('...type.STORE')`) rồi mới hiển thị — tuyệt đối không render thẳng chuỗi enum thô cho người dùng. Thêm một giá trị enum ở backend thì thêm ngay khoá i18n tương ứng (vi + en), nếu không cell sẽ hiện đúng chuỗi mã. Lưu ý: **mã do người dùng nhập** (mã location, mã cost center, mã lý do…) KHÔNG phải enum — hiển thị đúng mã đó qua `CodeText`.

Mẫu tham chiếu đã áp đủ các chuẩn: `src/features/master-data/locations/`, `cost-centers/`, `departments/`, `reason-codes/`.
